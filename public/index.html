Sentinel — wallet & transaction guard

Paste an ERC-20 approval and Sentinel screens it against a published, deterministic rule set — then returns a verdict (ALLOW / REVIEW / BLOCK) with the exact checks run and a Groth16 proof that the verdict followed the rules. Read-only: nothing is signed, nothing moves. Built for the zkVerify Agent Games Wildcard track. Chain: BSC mainnet.

How the verdict is decided

  • BLOCK — spender is the zero address, the token has no code, a bounded amount exceeds the wallet's balance, or the approval is unlimited and the spender is unknown or has no code.
  • REVIEW — unlimited approval to a known spender, spender has no code, spender is unknown (a contract outside the curated known-spender set), or any fact could not be observed (RPC error — fail closed, never ALLOW on unknown).
  • ALLOW — bounded amount, real token contract, balance sufficient, spender is a known contract from the curated set.

Thresholds: unlimited = amount ≥ 2255; "unknown" spender = a contract outside the curated known-spender set — public BSC full nodes prune historical state, so an on-chain age check is not possible (see README “Why an allowlist”). The proof (claim sentinel-v1) shows the verdict is exactly the output of this rule from the observed facts — it does not prove the RPC facts themselves; those are independently checkable on-chain.
